# 验证记录：远程调用结果的四种状态

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| 商品不存在 | 两种客户端都得到「不存在」 |
| 服务降级，返回 200 + SYSTEM_BUSY | 朴素客户端当成不存在；有类型客户端得到调用失败 |
| 商品服务超时 | 朴素客户端当成不存在；有类型客户端得到调用失败 |
| 清理下架商品时商品服务超时 | 朴素客户端删除全部 3 项；有类型客户端跳过这一轮 |
| 按 [3,1,9,1] 批量查询，按下标对应 | 3→键盘、1→显示器，名字错位；按 id 对应正确，9 为已下架 |
| 下单超时后直接重试 | 服务端创建 2 个订单 |
| 下单超时视为结果未知，按幂等键查询 | 服务端创建 1 个订单 |

## 五、误差、限制与不能推出的结论

- JSON 用正则解析，只为演示，不代表生产写法。
- 超时由 200ms 客户端超时与 500ms 服务端延迟构成，机器极慢时可能偏离；结论只依赖「客户端先放弃、服务端已经处理」。
- 服务端在同一 JVM 内，没有真实网络故障；断连、半开连接等不在本实验范围。

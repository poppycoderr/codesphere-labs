# 验证记录：单例作用域的缓存所有权

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| 同一份配置浅复制出两个容器 | 两个容器拿到同一个实例（#1） |
| 每个容器按配方重建 Provider | 容器内复用（#2、#2），容器间不同（#3） |
| 两个限定符绑定同一装饰器 | 同一实例；单独绑定的另一个限定符是另一个实例 |
| 不加锁，两个线程同时第一次取值 | 创建 2 次，拿到不同对象 |
| 加锁 | 创建 1 次，拿到同一对象 |
| 工厂返回 null，取 3 次 | `instance == null` 判断调用 3 次；独立标志调用 1 次 |
| 第一次创建抛异常 | 第二次重新创建成功，工厂共调用 2 次 |
| 装饰器不转发依赖元数据 | a ↔ b 的环检查通过（漏报） |
| 装饰器转发依赖元数据 | 报出 `a → b → a` |

## 五、误差、限制与不能推出的结论

- 装饰器与容器都是为对比写的极简实现，不代表任何框架；Spring、Guice 等的单例创建另有锁与循环处理。
- 并发场景用闸门制造交错，只说明不加锁时可能发生双重创建，不测量发生概率。
- 失败是否应该缓存是设计选择，本实验只展示「不缓存失败」这一种实现的行为。

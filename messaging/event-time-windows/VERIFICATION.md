# 验证记录：事件时间与窗口

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

事件（发生时刻 → 到达时刻，08:00:00 之后的秒数）：10→11、20→21、55→105、70→71、80→81。按发生时间，08:00 有 3 个，08:01 有 2 个。

| 设置 | 08:00 | 08:01 |
|---|---|---|
| 按到达时间归窗 | 2 | 3 |
| 按发生时间，允许晚到 5 分钟 | 3 | 2 |
| 按发生时间，不允许晚到 | 2 | 2 |
| 按发生时间，允许晚到 10 秒 | 2 | 2 |
| 按发生时间，允许晚到 30 秒 | 3 | 2 |

- 只在窗口关闭后输出（`suppress`，允许晚到 30 秒），事件 10、20、70 之后没有新事件：没有任何输出。
- 同样的设置，之后又来了 95、155 两个事件：输出 08:00 = 2、08:01 = 2。
- 事件 10、20、30、40 中间混进一个时间戳在一小时之后的事件，允许晚到 5 分钟：08:00 = 1，09:00 = 1，其余三个被丢弃。

## 五、误差、限制与不能推出的结论

- 用的是测试驱动，单个分区、单个任务。真实部署里流时间按任务各自推进，多分区时取决于各分区的进度，实验没有覆盖。
- 只验证了 Kafka Streams 4.3.1 的滚动窗口。其他流处理框架用水位线表达同样的概念，推进规则与默认值不同。
- 没有覆盖状态的检查点与故障恢复、恰好一次语义，也没有覆盖滑动窗口与会话窗口。
- 被丢弃的晚到记录在真实运行时会计入 `dropped-records` 指标并有一条日志，实验只看了输出结果。

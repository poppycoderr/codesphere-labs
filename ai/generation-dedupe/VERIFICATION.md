# 验证记录：重复点击又生成了一次

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| 先查后写，5 次并发 | 生成 5 次 |
| EXISTS 后 GET | EXISTS 1，GET None |
| 状态键与结果键分别过期 | 状态 done、结果 None |
| 普通 SET 回写 / KEEPTTL | TTL -1 / 60 |
| 空答案 | 被缓存，之后 3 次都拿到空串 |
| 三态 + 幂等键，5 次并发 | 生成 1 次，结果一致；完成记录 TTL 60 秒 |
| 空答案按失败处理 | failed 保留 2 秒，期间直接返回失败；过期后重新生成 |
| 持有者拿到租约后消失 | 约 0.3—1.2 秒后被接手 |
| 租约过期后旧持有者写回 | 被拒绝，保留新结果 |

## 五、误差、限制与不能推出的结论

- 假模型只模拟耗时与调用次数，不涉及真实的模型服务与计费。
- 单个 Redis 实例；主从切换时未同步的写入会丢失，租约与结果可能回退，需要下游按幂等键再校验。
- 租约时长固定为 500ms；真实生成耗时波动大，租约要能续期，本实验没有实现续期。

# 验证记录：微调样本的标签对齐与 LoRA 初始化

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| `labels=input_ids` | 损失等于「位置 t 的 logits 对位置 t+1 的词」，移位由模型内部完成 |
| 自己先左移一位再传入 | 损失变成「位置 t 对 t+2」；训练 150 步后输入 [1, 2, 3] 预测 5 而不是 4 |
| 填充位置标签仍是填充词 | 计入 10 个位置，其中 3 个目标是填充词；设 -100 后计入 7 个，损失随之改变 |
| 提示部分设 -100 | 计入损失的位置从 8 个降为 2 个；全保留训练时模型把提示也学会了 |
| 按词平均 | 等于 (2×短样本损失 + 8×长样本损失) / 10，不是两个样本损失的平均 |
| LoRA：A 随机、B 为零 | 初始输出不变；第 1 步只有 B 有梯度，之后两者都有 |
| LoRA：A、B 都为零 | 初始输出不变；3 步内两者都没有梯度 |
| LoRA：A、B 都随机 | 初始输出就偏离原层 |

## 五、误差、限制与不能推出的结论

- 模型很小且随机初始化，训练只用一两条固定序列，用来展示标签对齐的效果，不代表真实微调的收敛速度或质量。
- 词号直接写在代码里，没有使用分词器和对话模板；真实数据中「回答从哪个词开始」由模板决定，需要单独检查。
- LoRA 层是按公式手写的最小实现，没有使用 PEFT；PEFT 的默认初始化同样是 A 随机、B 为零，以其文档为准。

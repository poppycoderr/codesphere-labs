## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| 正确求和 / 写成减法 | 正常退出；3/3 与 1/3 组通过 |
| 语法错误 | 执行前被编译检查拒绝 |
| 运行时异常 | 非零退出，退出码 1 |
| 长时间休眠 | 墙钟 2.5 秒超时，杀掉进程组，退出码 -9 |
| 忙循环（CPU 软 1 秒、硬 2 秒） | SIGXCPU，退出码 -24 |
| 忙循环（软硬都是 1 秒） | SIGKILL，退出码 -9，与墙钟超时相同 |
| 申请 256 MiB（地址空间 128 MiB） | MemoryError，退出码 1 |
| 大量输出（文件上限 8193 字节） | 标准输出 8193 字节，判为超限 |
| 按确认时的摘要提交 / 原样重发 / 换内容重发 | 接受 / 保留原结果 / 拒绝 |
| 候选或判据改过之后提交 | 拒绝，确认失效 |

## 五、误差、限制与不能推出的结论

- 所有候选都是自己写的可信夹具；没有运行不可信代码，没有做逃逸测试，也没有多租户隔离验证，不能据此认为这套配置适合对外开放的判题服务。
- `MemoryError` 来自 Python 在地址空间限制下的行为，其他语言与运行时的表现不同；地址空间限制也不等于常驻内存限制。
- 退出码与信号的对应关系在本容器的 Linux 内核上观察得到；生产环境应由运行器自己记录是哪一个限制触发的，而不是事后从退出码推断。

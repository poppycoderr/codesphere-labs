# 验证记录：时间区间不重叠

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| 唯一键 `(member_id, starts)`，已有 09:00—12:00，再插入 10:00—11:00 | 插入成功，两条重叠 |
| 两个事务先查后插（REPEATABLE READ） | 2 个都提交成功，表里两条重叠 |
| 检查前先锁成员行 | 1 个成功，另一个检查时发现重叠而失败 |
| PostgreSQL 排他约束，两个事务并发插入重叠区间 | 1 个成功，另一个 `conflicting key value violates exclusion constraint` |
| 半开区间 `[09:00, 12:00)` 之后接 `[12:00, 15:00)` | 插入成功 |
| 闭区间 `[15:00, 18:00]` 之后接 `[18:00, 20:00)` | 被拒绝 |
| 另一个成员同一时段 | 插入成功 |

## 五、误差、限制与不能推出的结论

- 只验证了「同一成员、同一时间只有一个」这一种区间规则。容量类规则（同一时段最多 N 个）不能用排他约束表达，需要锁或计数行。
- 锁成员行的方案要求所有写值班的路径都先锁同一行；有一条路径不锁，它就失效了。实验只有一条写路径。
- MySQL 没有排他约束。实验没有比较用触发器、生成列加唯一键（把时间切成固定粒度的格子）等其他做法。

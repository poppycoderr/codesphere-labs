# 验证记录：遗留系统的精益切片

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

1. **字符化测试锁住旧行为**：旧服务在 2007 个用例上的输出与已批准文件完全一致；把退款计算移到接缝后面，输出同样一致。
2. **影子比对找出没有写在任何文档里的规则**。按「72 小时以上全额、24 小时以上一半、金额精确到分」直觉实现的新规则，2007 个用例中不一致 1748 个：
   - 19 个是退款档位不同：旧系统先把剩余时间截断成整小时，再用「大于 72」比较。距开场 72 小时 47 分时旧系统只退一半（25700 分），新规则全额（51410 分）；恰好 72 小时时旧系统也只退一半；
   - 1729 个只差不足一元的零头：旧系统把退款金额向下抹到整元。19950 分的全额退款，旧系统退 19900 分。
3. **把旧规则写成显式参数后一致**：`RefundPolicy.legacyCompatible()`（截断到整小时、抹去零头）与旧算法 0 个不一致。这两条规则是否合理，是业务决定，不在迁移中顺手修改。
4. **分流可以调大也可以调回**：每一档 2007 次退款，交给新模型的数量为 10% → 202 个，50% → 989 个，调回 0% → 0 个，100% → 2007 个；每一次返回值都与旧算法一致。

## 二、环境

见 [`evidence/environment.txt`](evidence/environment.txt)。组件版本：jdk 21、junit 5.13.4。

## 三、执行步骤

`mvn test` 运行 `LegacySliceTest` 的 3 个用例。用例由固定种子 2026 生成：费用 1—999 元（含分），距开场 0—200 小时（按分钟）；另加 7 个边界：72:00、72:30、72:59、73:00、24:00、23:59、0:00。已批准文件在首次建立实验时用 `-Dapprove=true` 生成，其 SHA-256 记录在证据中。

## 五、误差、限制与不能推出的结论

- 遗留服务与它的两条隐含规则是为本实验编写的，用来展示方法；真实系统的差异类型和比例会完全不同。
- 分流按报名 id 的哈希取模，10% 档实际是 202/2007；同一笔报名每次都落在同一侧，便于排查。
- 没有涉及数据迁移：退款规则是无状态计算，新旧两侧共用同一份报名数据。需要迁移数据的切片还要处理双写或回填，以及回滚时的数据方向。

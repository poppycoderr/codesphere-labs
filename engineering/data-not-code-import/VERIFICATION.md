# 验证记录：让模型产出数据而不是代码

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| 逗号切分 + 逐行提交 + 吞异常 | 报告成功 4 行、失败 4 行，脚本正常退出 |
| 库里实际的行 | 两条备注被截断（`"负责 A`、`"第一行`），状态 `P` 进了库 |
| 按 utf-8 解码读带 BOM 的文件 | 第一列名为 `'﻿id'`，`row['id']` 为 None |
| 按 utf-8-sig 解码 | 列名正常 |
| 标准 csv 解析 | 6 条记录，引号里的逗号与换行保留 |
| Schema 校验 | 3 条合格；报出非法状态、重复 ID、不存在的部门 |
| 不过滤直接单事务导入 | 唯一约束失败，整体回滚，库里 0 行 |
| 只导入合格记录 | 提交，库里 3 行 |

## 五、误差、限制与不能推出的结论

- 「模型生成的数据」是手写的固定样本，用来覆盖常见的格式问题；没有调用模型。
- 只用 SQLite 与 Python 标准库验证；其他数据库的事务、外键与批量导入接口不同。

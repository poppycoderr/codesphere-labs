# 验证记录：布隆过滤器的不存在与唯一约束

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| 已加入的 10000 个邮箱 | 被判为不存在的 0 个 |
| 构建后写入、写路径未更新过滤器的 100 个 | 100 个都被判为一定不存在 |
| 重建到一半就切换 | 10100 个已存在的邮箱里 5100 个被判为不存在 |
| 并发先查再插，没有唯一约束 | 两个都插入成功，表里 2 行 |
| 并发先查再插，有唯一约束 | 1 个成功、1 个被拒绝，表里 1 行 |

## 五、误差、限制与不能推出的结论

- 并发交错用闩锁固定为「两个请求都查完过滤器再写」，真实系统里这个窗口出现的概率取决于请求时序，但不为零。
- 过滤器在进程内存中；Redis 布隆过滤器模块等外部实现有同样的同步问题，没有在本实验中验证。

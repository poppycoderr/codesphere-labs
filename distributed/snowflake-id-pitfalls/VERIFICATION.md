# 验证记录：雪花算法式 ID 的前提

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

JDK 25.0.4.1。

1. 无保护的生成器：每毫秒 100 个、生成 2000 个，中途时钟回拨 5 毫秒，重复 500 个。带回拨检查的生成器在回拨后抛出 `IllegalStateException（clock moved backwards by 5 ms）`。
2. 带回拨检查的生成器重启（重启期间时钟回退 5 毫秒）后继续生成：重复 500 个。重启时恢复了上次持久化的时间戳：抛出异常，拒绝生成。
3. 同一毫秒内生成 5000 个：序列号直接回绕时重复 904 个；序列号用完时等到下一毫秒，重复 0 个。
4. 两个实例都用机器号 5，同一毫秒各生成 100 个：重复 100 个。机器号取 IP 的低 10 位时，10.0.0.5 与 10.0.4.5 都得到 5。把主机名哈希到 1024 个机器号，至少两个实例同号的概率：10 个实例 4.3%，30 个 34.9%，50 个 70.4%，100 个 99.3%。
5. 实例 B 的时钟快 3 毫秒：B 先生成的 ID 比 A 两毫秒之后生成的 ID 更大。
6. 41 位毫秒时间戳可用 69.7 年，纪元取 2020-01-01 时用到 2089-09-06。ID 在纪元之后 24.9 天超过 2^53；72477573120024577 转成 `double` 再转回是 72477573120024576。单个机器号每秒最多 4096000 个。

## 五、误差、限制与不能推出的结论

- 时钟是测试代码给的，回拨的幅度与时机是构造出来的；真实环境里时钟回拨多大、多频繁，取决于时间同步的配置，没有测量。
- 撞号概率按「哈希均匀分布」计算，是生日问题的精确公式，不是模拟。
- 只实现了最常见的位数分配；各开源实现的位数、回拨时的处理与机器号分配方式各不相同，没有逐个验证。
- 没有覆盖闰秒、虚拟机暂停与迁移对时钟的影响。

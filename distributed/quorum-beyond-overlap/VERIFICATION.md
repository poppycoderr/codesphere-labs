# 验证记录：W+R>N 之后还缺什么：quorum 的确定性模拟

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| W=2、R=2，读时比较版本 | v2（最新） |
| 同样的读，取最先返回的副本 | v1（旧值） |
| W=1、R=1 | v1（旧值） |
| W=2 只有 1 个副本确认，客户端收到失败；随后从不同副本 R=2 读 | 一次读到 v3，一次读到 v1 |
| 最后写入获胜，后发生的写入来自时钟慢 10 的客户端 | 保留先发生的写，后发生的被丢弃 |
| 两个客户端基于同一版本并发写，版本向量 | 保留两个值；合并写回后剩一个 |
| 宽松 quorum：写入落在 C 与备用节点 D，读 A、B | v1（W+R=4>3，集合不相交） |
| 会话写入后 R=1 读到落后副本 | v1；记住版本号、拒绝旧版本后改读 A 得到 v5 |

## 五、误差、限制与不能推出的结论

- 这是对规则的模拟，不涉及网络、超时与真实存储引擎；具体系统（Cassandra、Riak、DynamoDB 风格的存储）的行为以各自文档为准。
- 没有模拟读修复与反熵；它们会让旧值在一段时间后被修正，但不改变本实验各场景在读的那一刻的结果。

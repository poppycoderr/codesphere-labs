# 验证记录：分桶库存：调整桶数是一次迁移

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| 10 件拆 3 个桶 | 整除合计 9；余数分给前面的桶 4/3/3 |
| 只扣自己的桶 | 10 个请求成功 7 个，误判售罄时其他桶还有 6 件 |
| 空桶时依次试其他桶 | 10 个全部成功 |
| 客户端迁移期间 3 笔扣减 | 被新桶覆盖，总共能卖 13 件 |
| 缩容后旧路由、不校验版本 | DECR 已删除的桶得到 -1，扣减不计入任何现存的桶 |
| 带版本校验 | 旧版本被拒（-2），重读布局后成功 |
| 并发扣减 + 5 次调整桶数 | 恰好卖出 1000，剩余 0，没有负数桶 |

## 五、误差、限制与不能推出的结论

- 单个 Redis 实例；集群模式下依赖 {sku1} 哈希标签让所有桶落在同一个槽，本实验没有启动集群。
- 迁移脚本执行期间 Redis 不处理其他命令，桶数很大时会阻塞；本实验最多 7 个桶。
- 客户端迁移的丢失用固定的交错复现，不依赖并发时序。

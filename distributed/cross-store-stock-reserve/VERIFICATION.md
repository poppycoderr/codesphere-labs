# 验证记录：跨存储库存预扣：Redis 预扣、MySQL 扣减与对账

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 场景 | 结果 |
|---|---|
| 朴素：数据库拒绝（下架） | 方法返回 false，Redis 9、数据库 10 |
| 朴素：调用方提交时连接断开 | 方法已返回 true，catch 没执行，Redis 9、数据库 10 |
| 朴素：取消时数据库失败后重试 | Redis 加回两次，11 对 10 |
| 修正：数据库拒绝 | 立即释放预占，两边一致 |
| 修正：提交时连接断开 | 保留预占，对账按流水释放后一致 |
| 修正：三个崩溃点 | 对账一次恢复一致，再对账处理 0 项 |
| 修正：同一订单取消两次 | 只加回一次 |
| 修正：50 个订单并发抢 10 件 | 成功 10 个，两边一致 |

## 五、误差、限制与不能推出的结论

- 崩溃用抛异常模拟，提交失败用 KILL 连接模拟；真实的进程崩溃、网络分区与 Redis 主从切换丢写没有覆盖。
- 对账在崩溃之后执行，没有与进行中的请求并发；实际系统只处理超过一定时长的预占。
- 提交时连接断开在本实验中事务被回滚；提交已生效但客户端没收到确认的情况，由「提交之后崩溃」的场景覆盖了同一个对账分支。

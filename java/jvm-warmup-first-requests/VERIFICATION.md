# 验证记录：进程刚启动时的前几个请求

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

单次调用耗时（微秒）：

| 参数 | 第 1 次 | 第 2—10 次 | 第 91—100 次 | 第 901—1000 次 | 第 9901—10000 次 |
|---|---|---|---|---|---|
| 默认 | 28089 | 308 | 85.3 | 22.7 | 9.8 |
| `-Xint` | 28359 | 394 | 392 | 392 | 392 |
| 只用 C1 | 26858 | 278 | 67.6 | 15.4 | 10.5 |
| AOT 缓存 | 13857 | 299 | 85.7 | 11.5 | 9.3 |
| 先预热 3000 次 | 106 | 67.0 | 22.2 | 20.0 | 9.3 |

| 参数 | 从启动到第一个响应 | 前 100 次调用合计 |
|---|---|---|
| 默认 | 46.8 ms | 44.3 ms |
| `-Xint` | 45.2 ms | 67.5 ms |
| 只用 C1 | 44.8 ms | 39.8 ms |
| AOT 缓存 | 32.0 ms | 28.9 ms |
| 先预热 3000 次 | 119 ms | 2.9 ms |

脚本断言的是倍数关系：默认参数下第 1 次调用比稳定后慢 100 倍以上、第 2—10 次慢 5 倍以上、第 91—100 次慢 2 倍以上；只用解释器时一万次之后仍慢 10 倍以上；AOT 缓存下第 1 次调用不超过默认的 85%、启动到第一个响应不超过默认的 90%；预热后第一个真实请求不到默认第 1 次调用的 5%。

## 五、误差、限制与不能推出的结论

- 处理函数很小，没有框架。真实服务的第一次请求还要初始化框架的各层、建立连接池和 TLS 会话，绝对数值会大得多；这里只说明各阶段的相对关系。
- 耗时取决于机器与 CPU 限额。限额越小，JIT 编译线程与业务线程争抢越明显，预热越慢；实验固定为 2 个 CPU，没有比较其他限额。
- AOT 缓存的训练运行与正式运行用了同一段代码和同一个 jar。训练运行的负载与线上不同、或者 jar 变了，效果会不同，实验没有覆盖。
- 预热用的输入与正式请求走同一条代码路径。预热没有覆盖到的分支，第一次走到时仍然是慢的。
- 没有覆盖反优化（预热时的假设被真实流量打破后退回解释执行）。

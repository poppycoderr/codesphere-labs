# 验证记录：内容相同的字符串

> 轻量记录：按 [验证标准](../../docs/verification-standard.md) 的十个部分合并为七节。

## 一、待验证结论与实际结果

| 做法 | 每个字段占用 | 构建 200 万个字段 |
|---|---|---|
| 每条记录各建一个 `String` | 64.5 字节 | 167 ms |
| 解析后调用 `intern()` | 0.4 字节 | 249 ms |
| 用自己的 `HashMap` 归一 | 0.4 字节 | 182 ms |
| 各建各的，加 `-XX:+UseStringDeduplication` | 24.4 字节 | 183 ms |
| 各建各的，字段末尾多一个汉字 | 87.7 字节 | 226 ms |

脚本只断言字节数落在预期的范围内，不断言耗时。

## 五、误差、限制与不能推出的结论

- 堆占用是用 `Runtime` 在垃圾回收前后的差值估算的，不是逐对象统计，有少量误差。
- 字段长度约 20 个字符、取值 100 种是实验设定。字段越短，对象头占的比例越高；取值种类接近记录数时，归一没有收益，还多一张表。
- 构建耗时是单次运行的结果，只用来看量级。`intern()` 的字符串表在条目很多时的表现没有测量。
- 字符串去重只在 G1 等支持它的收集器上有效，在后台进行，实验里等了几轮回收之后才测量；没有测量它对回收暂停的影响。

# 验证标准

## 一、验证级别

| 级别 | 适用 | 本仓库的做法 |
|---|---|---|
| 文档核验 | 版本敏感的定义、默认值 | 在 codesphere 文章中引用官方文档，不在本仓库建实验 |
| 就地实验 | 单个 JDK 程序、单个容器可复现 | 轻量实验或黄金样板 |
| 项目级验证 | 需要启动 Spring Boot、组合多个中间件 | 下一阶段用 Spring Boot 4 + Testcontainers 集中建设 |

只有概念讲解的文章不需要实验。正文只要使用「实测」「性能提升」「默认行为」「一定发生」等可验证的表达，就要有对应证据，否则降低表述强度。

## 二、黄金样板与轻量实验

| | 黄金样板 | 轻量实验 |
|---|---|---|
| 目的 | 确定一类实验的证据格式 | 为存量文章补上可复现的核心链路 |
| `VERIFICATION.md` | 十个部分完整填写 | 合并为七节：结论、环境、步骤、证据、限制、复现、历史 |
| 证据 | 完整原始输出、统计汇总、规范化说明 | 核心输出与环境 |
| 断言 | 覆盖正文每一条关键结论 | 覆盖正文中的关键数字或现象 |

## 三、VERIFICATION.md 的十个部分

1. 待验证结论
2. 适用版本与环境
3. 场景与数据集
4. 执行步骤
5. 原始证据索引
6. 实际结果（引用 `evidence/` 中的具体文件）
7. 结果解释
8. 误差、限制与不能推出的结论
9. 复现与清理命令
10. 验证历史（日期、版本、结果是否变化、文章是否需要更新）

## 四、完成定义

一个实验只有满足以下条件，文章中才能写「已验证」并链接到它：

- [ ] 能在声明的环境和版本中运行；
- [ ] `make verify` 一条命令完成核心验证；
- [ ] 断言覆盖正文的关键结论，而不只是启动成功；
- [ ] 环境、配置、数据、命令和执行顺序已记录；
- [ ] 原始输出已归档，并与人工解释分离；
- [ ] 通过 `make check`（含敏感信息扫描）；
- [ ] 性能场景写明预热、次数、并发和统计口径；
- [ ] `VERIFICATION.md` 说明限制和不能推出的结论；
- [ ] CI 至少覆盖构建、测试和轻量验证；
- [ ] 文章链接到实验目录、验证记录和固定 commit，版本和数字与证据一致。

## 五、实验结果与文章不一致时

以证据为准修改文章，不让实验迁就原稿。在 `VERIFICATION.md` 的验证历史中记录原数字和新数字；随机性导致的差异（并发、调度、耗时）在「误差、限制」中写明范围。
